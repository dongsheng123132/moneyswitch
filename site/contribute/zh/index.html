第一次提 PR

从你的 Fork，到上游 main

  1. 选择一个小问题

    从能复现、能用一句话解释的问题开始。先看 CONTRIBUTING.md；涉及部署或付款行为，还要读 SPEC.md。较大改动先讨论。

  2. Fork，再克隆你自己的仓库

    点击 Fork。把下方 YOUR_GITHUB_USER 替换为你的 GitHub 用户名，或直接从自己 Fork 的 Code 菜单复制地址。

    git clone https://github.com/YOUR_GITHUB_USER/moneyswitch.git
cd moneyswitch
git remote add upstream https://github.com/dongsheng123132/moneyswitch.git
git switch -c docs/my-first-fix

  3. 修改源文件，验证结果

    只改这次问题需要的内容。首页、试用页和贡献页直接维护在 site/；博客正文在 docs/blog/，修改后运行 node scripts/build-blog.mjs，把生成页面一并提交。

    按 CONTRIBUTING.md 的要求运行检查。网站改动要预览中英文与手机宽度，写清实际验证了什么、还有什么没有验证。

  4. 提交改动，推送到自己的 Fork

    先看 diff，把示例路径换成你确实要提交的文件。凭据和本地钱包数据不要放进提交。

    git diff
git add path/to/changed-file
git commit -m "docs: clarify the trial setup"
git push -u origin docs/my-first-fix

  5. 选择跨 Fork 比较，提交 PR

    打开上游比较页，选择 compare across forks。base repository 选 dongsheng123132/moneyswitch，base 选 main；head repository 选自己的 Fork，compare 选 docs/my-first-fix。

    检查 diff，写清改了什么、如何验证。本人阅读 CLA 并同意后，再勾选相应项。提交 PR 是进入维护者审查，并不代表已经获批或合并。

好的 PR，说明具体结果就够了

例如：“试用说明重复要求付款。我改成了观察技能自动发起的那一次请求，并检查了中英文页面。”比只写“优化文档”更容易审查。界面改动有必要时附上截图。

提交前，了解这几件事

贡献代码，需要购买代币或使用主网吗？

不需要做主网付款。可以从测试网试用或文档问题开始。离线测试按贡献指南操作；需要链上付款验证时，使用自己的测试钱包，不使用维护者的共享钱包。

这个云钱包的边界是什么？

一套部署为一个出资方花钱，Agent 各自使用有限额的 MoneyKey。目前支付范围是支持的 USDC / x402 API。这仍是自托管热钱包：能读钱包数据和解锁文件的人就能动用资金。改变付款策略、部署方式或信任边界，要遵循规格说明。

CLA 由谁确认？

由提交者本人阅读 CLA.md，同意后在 PR 中勾选。阅读本页面不会签署协议，指南也不会代你接受条款。

提交 PR，一定会有奖励吗？

我们可能根据参与和反馈情况酌情给予奖励，具体安排另行说明。提交或合并 PR 都不保证获得奖励，也没有承诺固定金额。

哪些信息不能发在公开 Issue 或 PR？

MoneyKey、审批 PIN、恢复词、私钥、管理员令牌与登录链接、含凭据的原始日志，以及钱包数据。请提供脱敏示例；安全漏洞通过私密安全报告入口反馈，并遵循 SECURITY.md。

一个清楚的问题报告，也是一份贡献。

暂时没有修复方案也没关系。告诉我们部署卡在哪一步，或你希望接入哪个 Agent 工作流。
