邀请你试用 MoneySwitch：两个 Agent，一个自己托管的钱包

你是不是也在一台电脑上用 Codex，另一台上用 Claude Code，云端还跑着其他 Agent？我们想邀请这样的开发者试试 MoneySwitch，看看把它放进真实工作流程后，哪些地方能用，哪些地方还不顺。

MoneySwitch 是可云自托管的可编程多 Agent 支出钱包。 钱包放在你控制的服务端，每个 Agent 拿一把独立的 MoneyKey，按规则请求付款。当前通过 x402 支付 Monad 和 Base 上的 USDC，默认只开测试网。

这次是早期自部署试用。你部署、你控制服务，一台实例只替一个出钱的人或组织花钱；目前没有托管平台注册账户，也没有共享的客户余额。

适合谁来试

  • 已经在用至少两个 Agent，或在不同机器上运行同类 Agent。
  • 能自己部署一个服务，并将钱包服务与 Agent 的系统权限隔离。
  • 想验证 Agent 花钱时的预算与审批流程，愿意描述具体哪里好用、哪里卡住。

这次不需要投入真钱。建议完成的是一笔 Monad 测试网的 0.01 测试 USDC 付款。测试 USDC 没有真实货币价值。首轮不设金钱奖励，也不提供美元 API 额度或模型订阅赠送。

想请你试这几件事

试用详情页提供当前的部署入口。我们希望你走一遍下面的流程：

  1. 部署钱包服务。 按自托管文档启动，保留测试网配置，在后台创建钱包，按钱包页的水龙头指引领取 Monad 测试网 USDC。不要让 Agent 读写服务的钱包文件、数据库或管理员凭据。
  2. 接入两个 Agent。 各发一把测试网 key，允许测试接口。两把 key 都设置总额度 0.05、日额度 0.05、单笔上限 0.02，单位都是测试 USDC。创建时，把 A 的审批线留空，把 B 的审批线设为 0.01。将各自生成的技能说明交给对应 Agent；确认码交给负责这把 key 的人，别贴给 Agent。
  3. 观察第一笔测试付款。 生成的技能会引导 A 完成 Monad 测试网上的 0.01 测试 USDC 付款。查看结果和交易哈希，不要再手动重复同一笔测试。若结果不确定，先查清状态再决定下一步。
  4. 试一次人工决定。 B 的付款金额达到 0.01 审批线，应当等待人处理。打开链接，输入这把 key 的确认码，或由管理员审批，再让 Agent 继续同一个请求；也看看拒绝路径是否清楚。
  5. 看账单，再撤销一把 key。 能否认出 key、金额、网址、链、交易哈希和扣款状态？撤销 A 的 key 后，让 A 只查询 GET /v1/status，确认请求被拒绝，不需要再次付款。另一个 Agent 有自己的 key；撤销不会退回已经付出的款项。

卡住也可以直接反馈，不用先把所有步骤“做成功”才算参与。

我们想听到什么反馈

请说清楚你想完成什么、用了哪些 Agent 和机器，以及从哪一步开始看不懂或走不下去。尤其想了解：

  • 自部署是否清楚？从另一台电脑接入时卡在哪里？
  • key 的额度和人工审批是否符合预期？
  • 能不能分清已经扣款、没有扣款、结果不确定？
  • 撤销后，哪些事被阻止了、哪些事已经发生，是否容易理解？
  • 你真想让 Agent 付费调用的 API 是什么，它是否支持兼容的付款方式？

我们需要具体的问题和缺失的流程。如果你的结论是“我暂时不需要这个”，也欢迎直接说原因。

当前产品的边界

MoneySwitch 不能支付任意模型订阅。现在支持的是 x402 付款路径，卖家需要接受兼容的付款方式和链。账单记录支付信息，还不能解释整个 Agent 任务，也不会判断它买的东西值不值。

钱包是服务端热钱包。不给 Agent 机器下发私钥，可以减少这些机器需要保管的秘密，但你仍然需要信任钱包服务；服务器被攻破，资金也可能有风险。本次先用测试网，考虑主网前再认真看部署与安全文档。

开始试用，留下反馈

打开 MoneySwitch 试用指南，之后可以提交 GitHub 体验反馈，写下部署方式、预期结果、实际结果和复现步骤。必要时附截图或脱敏后的响应，方便我们定位。

不要公开 MoneyKey、确认码、管理员令牌、恢复词或私钥。公开反馈前，也请删掉请求网址里的敏感参数和个人信息。安全漏洞请按仓库的安全报告说明反馈，不要在公开 Issue 里发布利用细节。

这次最想验证的是：一个钱包、分别授予花钱权限，是否适合你真实使用多个 Agent 的方式。你的体验会帮助我们决定下一步先修什么。
