  • 达到或超过审批线，先交给人决定。
  • 按 Key 查付款记录，并撤销不再需要的 Key。

一次完整的小实验

让两个 Agent 各拿一把 Key

  1. 部署自己的钱包服务

    按云服务器部署指南配置 Docker 与 HTTPS，或按源码启动说明运行。服务与 Agent 使用隔离的机器或系统权限，让 Agent 只能通过网络使用 MoneyKey。

    首次启动的管理员登录链接只供你使用。在钱包页创建钱包，自己保存恢复词，使用钱包页的水龙头指引领取 Monad 测试网 USDC。不要充值主网资金来完成这次试用。

  2. 分别给 Agent A 和 B 发测试网 Key

    在 Key 页创建两把命名不同的 Key，例如 laptop-codex 和 cloud-claude。都选择“测试网”，保留“允许测试付款接口”。下面是一组可选的测试参数，单位都是测试 USDC：

    参数Agent AAgent B
    总额度 / 日额度0.05 / 0.050.05 / 0.05
    单笔上限0.020.02
    审批线留空0.01

    把各自的技能段落交给对应的 Agent，确认它能访问你的 HTTPS 服务地址。确认码只给人，管理员令牌、恢复词和 Key 的确认码都不放进 Agent 技能里。只有一个 Agent 时，也可以先后试两把 Key。

  3. 观察付款和审批

    勾选测试接口后，技能会引导 Agent 查询额度，并向 https://app.moneyswitch.dev/x402-testnet/check 发起一次 0.01 测试 USDC付款。不要再手动重复同一笔测试。

    A 应在额度内完成付款；B 的金额达到审批线，应先返回审批链接。你用这把 Key 的确认码批准，或由管理员在后台批准，然后 Agent 按技能说明继续该请求。保留成功的交易号；如果出现 charged: maybe 或超时，先查看账单，不要自动重试。

  4. 查账、撤销，再说说体验

    在账单页核对两把 Key 的记录：金额、URL、链、扣款状态，以及已确认付款的交易号。撤销 A 的 Key，再让 A 只查询状态 GET /v1/status，应被拒绝；不需要再付一笔钱。

    记下最不清楚的一步、遇到的错误，以及你实际想让 Agent 购买的服务。测试币领不到、服务器部署不起来，都可以直接反馈。

开始前你可能想知道

“云钱包”是谁在保管？

服务部署在你自己的服务器，由你管理钱包和数据。Agent 获得的是受额度限制的访问 Key。谁能读取服务器的钱包数据和解锁文件，谁就能动用钱包；自托管需要你保护服务器，后续使用主网时也适合作为小额支出钱包。

每个 Agent 都有独立钱包地址吗？

它们使用同一出资方的钱包，各有独立 Key 和限额。Key 的额度是支出上限，不是为它单独存入的一份余额。同一钱包地址在不同链上的余额也彼此独立。

有奖励吗？需要转发或好评吗？

我们会视试用与反馈情况，酌情给予奖励；具体形式与标准另行说明，不承诺参与即得或固定金额。反馈没有转发或好评要求，负面体验同样欢迎。测试币没有真实价值；服务器等自备环境可能产生费用。

现在还缺什么？

任务用途备注和按任务汇总的成本报表还没有做。子 Key 目前只有后端接口，没有创建界面。当前通过 Skill 和 HTTP 接入，不提供 MCP 接口，也不是开放注册的多租户托管服务。
