# 给 AI Bot 用的可编程 Web3 云钱包

AI Bot 已经能写代码、部署服务，也能判断该调用哪个 API。可当 API 开始收费时，我们究竟应该给它多大的付款权限？

“给它一个钱包”还没有回答这些问题：今天能花多少？能付给哪些服务？什么时候需要问人？怎样停掉一个 bot 的花钱权限，同时让其他 bot 继续工作？

这正是我们在做 MoneySwitch 时想解决的事：**给 AI Bot 用的可编程 Web3 云钱包，由你自己部署和控制。** 项目开源，也想邀请你通过实际试用、清楚的问题报告和 PR，一起把它做好。

![MoneySwitch：一个自己托管的 Web3 云钱包，为不同设备上的 AI Bot 分别授予花钱权限。](https://moneyswitch.dev/assets/img/cloud-wallet-2026-10/cover-zh.webp)

## 给 Bot 的，是一份花钱权限

假设一个研究 Agent 找到了付费数据接口，你希望价格合适时它能自己购买。同时，笔记本上的编程 Agent 需要另一份预算，云服务器上的后台 bot 则应该在任务结束后停止花钱。

MoneySwitch 把钱包放在一个服务里，再给每个 Agent 发一把独立的 **MoneyKey**。它代表按规则请求付款的权限，不包含钱包私钥。同一个出资方提供资金，不同 Agent 各有自己的额度和权限。

服务在签名之前检查日额度、总额度、单笔上限、允许域名和审批线。金额达到或超过审批线时，先等人决定；批准后也不能突破硬额度。撤销一把 key，这个 Agent 的后续请求会被拒绝，其他 Agent 仍然保留各自的权限。

这就是我们所说的“可编程”：规则由实际签署付款的服务执行，而不只是在提示词里提醒模型节省开支。每把 key 的额度是支出上限，不是为它单独存入的一份余额。

## 云钱包，是一个你自己运行的服务

你的 Agent 可能是笔记本里的 Codex、台式机上的 Claude Code，也可能是云端自己写的程序。它们可以通过 HTTP 和每把 key 生成的技能说明，连接同一个 MoneySwitch 服务。

“云”指的是你可以把这个服务部署到自己的云服务器。运行环境、数据和钱包都由你管理。当前产品是早期自托管软件，一台实例替一个出资方花钱，可以是你自己，也可以是你的组织。目前没有让不同客户注册、充值、分别保管余额的 MoneySwitch 托管账户。

这个服务仍然需要你信任和保护。它持有能够自动签名的热钱包；不把私钥下发到 Agent 机器，并不代表钱包服务器被攻破后资金也安全。服务与 Agent 应当有系统权限隔离，避免 Agent 能直接修改服务数据库或钱包文件，从而破坏原本的支出规则。

## 这里的 Web3，具体落在付款上

MoneySwitch 当前用 **USDC 通过 x402 付款**，支持 Monad 和 Base，默认只启用测试网。

Agent 通过 MoneySwitch 请求一个 API；兼容的卖家返回 HTTP 402 付款要求。MoneySwitch 检查这把 key 的规则，需要时等待人工审批，为允许的付款签名，再带上支付授权重试请求，最终返回内容和付款状态。

卖家必须接受支持的链和付款方式，钱包在对应链上也要有余额。它不能让任意网站都支持付款，也不是支持任意链的钱包，更不能直接购买 Claude 或 Codex 的订阅。Bot 是钱包的调用者，它所使用模型的账单仍是另一个系统。

付款结算后，账单可以提供 key、金额、URL、链和交易哈希。响应会区分 `charged: yes`、`no` 和 `maybe`。结果不明确时应先查清楚，而不是自动重试、冒着付两次钱的风险。让使用者知道发生了什么，和完成一次付款同样重要。

## 一起做一个你自己的 Bot 真能用的钱包

我们希望产品由真实运行 Agent 的开发者一起打磨。贡献可以从一个很小的问题开始：

- **修一处部署说明。** 哪一步跑不通，或者文档默认读者已经知道什么？复现后把这一步写清楚。
- **让问题可以复现。** 描述预期结果、实际结果和最小测试网例子；如果能补一个失败用例或范围清楚的修复，就更方便验证。
- **改善一种 Agent 的接入体验。** 用自己的 Agent 试一遍生成的技能和 HTTP 流程，把配置或报错时遇到的困难变成其他人能照着用的示例、说明。
- **把一次付款决定说清楚。** 如果审批页或账单让你不确定接下来会发生什么，先把这个具体场景带进讨论，再一起判断要怎么改。

不需要先做一个庞大的集成才能参与。一份解决真实障碍的小 PR，就已经有具体内容可以审查。涉及付款行为或权限的改动，先讨论范围，让实现和测试围绕说清楚的边界展开。

## 从测试币和一条完整流程开始

试用用到两把 Agent key，各在 Monad 测试网上支付一笔 0.01 测试 USDC。一把 key 在规则内直接付，另一把先等人批准；之后查看账单，撤销一把 key，确认后续请求停止。测试 USDC 没有真实货币价值。

具体配置和技能首付流程请按试用指南操作。部署不成功、Agent 连不上，也可以直接反馈卡住的步骤，不必等付款成功后才参与。公开材料只放脱敏信息，不要贴 key、确认码、恢复词或管理员凭据。

我们可能根据试用与反馈情况酌情提供奖励；提交或合并 PR 不等于自动获得奖励。
