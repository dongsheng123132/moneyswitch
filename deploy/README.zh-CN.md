# MoneySwitch 自建部署

个人、团队和企业运行同一个服务。数据库、预算、审批、通知设置和加密钱包都保存在自己的服务器。浏览器是管理界面；AI 拿受限 MoneyKey，通过 skill 调用 `/v1/fetch`。管理员令牌和钱包密码不交给 AI。

## Docker + HTTPS

要求 Linux、Docker Compose、一个指向服务器的域名。官网可以保持静态托管，后台使用独立子域名。仓库根目录执行：

```sh
cp deploy/.env.example .env
mkdir -p deploy/secrets
# 旧方式的钱包密码文件：docker-compose 仍会挂载它，所以文件必须存在，但留空即可（空 = 未配置）。已有文件不要覆盖。
test -e deploy/secrets/wallet_password || (umask 077; touch deploy/secrets/wallet_password)
docker compose build server
docker compose up -d server
docker compose ps
curl --fail http://127.0.0.1:4020/healthz
```

修改 `.env` 的域名、端口和允许付款的链。将 `deploy/moneyswitch.caddy` 的域名和端口替换为实际值，安装在自己的 Caddy 配置中。先 `caddy validate`，再 reload；80/443 用于 HTTPS，4020 只监听本机。反向代理必须保留 Authorization 头和 SSE，不做付费请求自动重试。

首次启动会生成管理员令牌和 30 分钟一次性初始化链接。仅在私有终端查看 `docker compose logs server`，用 HTTPS 后台打开初始化链接，创建钱包并给 AI 创建预算 Key。日志含首次管理员凭据，勿公开分享。后续登录也可在后台输入管理员令牌。

### 钱包：默认自动解锁，恢复短语才是备份

后台「创建钱包（推荐）」不需要设置密码：服务器在数据目录 `/data` 里保存一个随机解锁密钥（文件名 `wallet-unlock-<钱包地址>.secret`，名字里带地址，不会和别的钱包的密钥混淆），重启后自行解锁，不再因为重启而锁死。真正的备份是 **12 个单词的恢复短语**：创建时抄在纸上，并在后台答对其中两个词；通过之前后台的充值/复制场合（收款卡片、右上角的地址标签）都不显示钱包地址（只有「更换钱包」对话框会只读地显示它，并注明「这个钱包将被停用，不要再向它转钱」）。MetaMask、OKX 钱包等标准钱包导入这 12 个词，看到的地址与服务器上的相同。

`wallet.json` 里有一个不含秘密的小标记，记录这个钱包是「自动解锁」还是「密码」模式；后台状态、解锁顺序和备份下载都以这个标记为准，而不是看目录里碰巧有哪些文件。

启动时的解锁顺序：`MONEYSWITCH_WALLET_PASSWORD` / `MONEYSWITCH_WALLET_PASSWORD_FILE`（**非空**才算数）→ 这个钱包自己的解锁密钥 → 否则保持锁定。**空变量、空文件、只有空白的文件都视为没有配置**，所以上面那个留空的占位文件是无害的；它是旧方式，不需要再往里写密码。某个来源存在但打不开钱包时，日志会分别报错并写明各自的原因（`env_wrong`、`secret_missing`、`secret_empty`、`secret_unreadable`、`secret_wrong`，不含密码），后台显示「自动解锁已损坏」并在总览顶部提示，之后仍会尝试下一个来源；过期的环境变量密码不会被当成密钥出错的原因，反过来也一样。已有的钱包保持原来的模式，升级不会自动把它们改成自动解锁。

必须诚实地说明这个取舍：**谁能读取 `/data`，谁就能动用这个钱包**（包括磁盘快照和数据目录备份）。服务器会把 `/data` 和解锁密钥限制为只有自己的账户可访问，并**检查**是否真的生效：Windows 上设置只含当前用户和 SYSTEM 的受保护 ACL（文件权限位 0600 在 Windows 上没有意义），Linux/macOS 上目录 0700、密钥 0600；每次启动都会重新设置并检查。设置不成功（例如网络盘、忽略权限的挂载卷）时服务器照常运行，但后台钱包页会出现红色警告，总览顶部也有红色横幅（`health.secret_protected=false`），此时请只放极少的浮存。这只防「别的账户」，防不了同一系统用户。所以：

- 把它当作小额「浮存」热钱包：默认超过 50 USDC 后台就会警告（`MONEYSWITCH_WALLET_FLOAT_LIMIT` 可改），多余的转到你自己掌控的钱包。
- 团队使用请单独部署一台服务器，不要在同一台机器、同一系统用户下运行 AI；AI 只拿 MoneyKey 远程调用。
- 保护好 `/data` 及其备份，等同保护私钥。`/data/retired/` 里是旧钱包的凭据，同样敏感。
- 导入已有钱包时只保存那一个账户的私钥，**不保存恢复短语**（一个短语可能控制很多账户，不该放在热钱包服务器上）；永远不要导入同时控制着其他资金的短语或私钥，它必须是专门给 AI 付款准备的小额钱包。导入时可以填「你预期的地址」，密钥对不上就拒绝。
- 不能接受这一点时，在后台选「高级：每次重启都要输入密码」，或之后在「钱包 → 危险操作」里关闭自动解锁。此时不保存任何密钥，重启后钱包保持锁定，直到有人输入密码。

密码丢了、或怀疑私钥泄露时，用「钱包 → 危险操作 → 更换钱包」：旧的钱包文件（以及解锁密钥）先被**复制**到 `/data/retired/` 并核对无误，再用新文件覆盖原名（`wallet.json` 任何时刻都不会缺失，中途崩溃也总留有一对能打开的文件），绝不删除，新钱包接替；Key、预算、审批和历史都保留。旧钱包里的资金仍在旧地址，后台「已停用的钱包」会列出它们的实时 USDC 余额，并说明如何用恢复短语或 `retired/` 里的文件找回。**钱包被锁定、密码丢了时也能更换**（只移动文件，不解密）：上一版本创建的密码钱包重启后处于锁定状态，密码丢失、恢复短语也没确认过时，后台钱包页（危险操作区会自动展开）和设置向导（解锁表单下方）里的更换对话框都会显示要输入的当前地址。只要有付款请求正占用着钱包（进程内计数，不是看数据库），更换和锁定都会被拒绝（409 `WALLET_BUSY`），稍后再试；万一钱包在请求开始之后被换掉，旧的签名器拒绝签名，扣款状态为 no。服务重启时，上次进程遗留的 `reserved` 付款会在对外服务之前处理：已经签过名的转为 `unknown`（交给链上对账），没签过的直接标为失败并释放预算。

数据目录里还会出现 `wallet.json` 丢失但凭据文件仍在的情况（最常见的原因是挂载错了目录）：后台会明确提示并要求你确认，而不是悄悄地让你新建一个空钱包；服务器本身也不会去覆盖或删除那些文件。

## 链和资金

默认只启用 Monad 测试网 `eip155:10143` 和 Base Sepolia `eip155:84532`。主网须明确改为 `eip155:143,eip155:8453`，默认链也必须在允许列表内。每条链只允许其指定 USDC；不换币、不跨链。一个地址在不同链的余额独立，付款账本记录实际链，对账按该链查询。

个人使用可只建一把 Key。团队管理员给每名成员创建独立 Key，设总额、每日限额、单笔限额、允许域名和审批阈值；成员只能查看自己的预算和历史。子 Key 不能绕过父 Key 的限制。先在测试网走通真实服务，再按自己的资金策略启用主网。

## 备份、升级和回滚

同一 SQLite 数据卷只运行一个服务实例，不做多副本写入。停机备份包含整个 `/data`，包括加密钱包、自动解锁密钥 `wallet-unlock-<地址>.secret`、`retired/` 里的旧钱包文件、SQLite 和管理员凭据；**这份备份等同于私钥，也属于秘密**，谁拿到它谁就能动用钱包。它不能代替恢复短语：服务器和磁盘一起丢了，靠的是抄在纸上的 12 个词。若仍在用旧的密码文件方式，宿主机上的密码文件另行备份。

```sh
docker compose stop server
mkdir -p backups
docker compose run --rm --no-deps --user root --entrypoint tar server -C /data -czf - . > backups/data-$(date +%Y%m%d-%H%M%S).tgz
docker compose start server
```

备份目录设为仅管理员可读。升级前记录旧镜像 ID、Git commit 和备份；从同一个代码源重新构建新镜像后切换。回滚使用旧镜像。本版本的数据库迁移（`0007_wallet_lifecycle.sql`）只增不删（两个可空列和一张新表），旧镜像打开已迁移的数据库不会出错（`deploy/upgrade-us.sh` 升级失败时的自动回滚就是这样做的，并有测试覆盖）；想要最保守，或者在新版本上已经把钱包改成自动解锁/更换过之后（旧镜像打不开自动解锁的钱包），请用升级前的数据备份恢复。不要执行 `docker compose down -v`，它会删除持久数据。

历史收费亭表仍保留在数据库中；v0.6 不提供卖方收费亭接口。存档标签 `archive/tollbooth-v0.5` 供历史代码查询。

## 验收

检查 `/healthz`、后台初始化、钱包创建后的恢复短语核对、**重启服务后钱包仍是解锁状态且不需要任何密码**（总览没有「自动解锁已损坏」提示）、手动解锁（密码模式）、Key 创建和重置、个性化 skill、超预算拦截、审批通过后只付一次、通知测试、扣款状态 yes/no/maybe、数据库重启后保留。可运行 `node scripts/deploy-smoke.mjs` 对已构建包做独立沙箱验收；它不会使用已有钱包。通知测试先用自有沙箱接收端，生产渠道由管理员配置。发布记录应注明是否实际验证 HTTPS、容器重启、真实链付款，不能把离线模拟当成真钱交易。
