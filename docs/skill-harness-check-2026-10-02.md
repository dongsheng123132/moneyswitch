## 结论

用户提供的 DSH 反馈证明了技能安装和额度查询成功，不证明 x402 付款成功。实际私有技能存在，格式与当前生成模板一致；没有修改该文件，也没有将其中的 MoneyKey 复制到仓库或报告。

“整台 Windows TLS 栈不可用”的诊断过于宽泛。复测相同接口、相同本机客户端，仅改变执行权限上下文，得到如下结果：

| 本机调用 | 受限沙箱 | 沙箱外 |
|---|---|---|
| Windows `curl.exe` 8.13.0 / Schannel，经 127.0.0.1:7897 | `AcquireCredentialsHandle` / `SEC_E_NO_CREDENTIALS` | `/healthz` 返回 `{"ok":true}` |
| PowerShell `Invoke-RestMethod` | SSL 连接失败 | `/healthz` 返回 `{"ok":true}` |
| Python 标准库 / OpenSSL，正常证书校验 | `/v1/status`、`/v1/history` 均 HTTP 200 | 不需要另行放宽权限 |

这证明问题与当前沙箱执行环境有关，不能据此要求用户修复 Windows TLS。DSH 很可能遇到同类限制，但本次没有启动 DSH 的独立模型会话来证明它的具体内部根因。

- 安装提示正常只要求两句话：接入结果、今日可用、单笔上限和审批线，并说明没有付款。
