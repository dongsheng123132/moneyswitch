# 三个项目开发方案：钱包 · 服务 · 城（2026-09-28）

> 主会话综合出的方案。依据：两轮工作流，共 16 个子代理（调查、三套设计、评审），关键事实由主会话复核。
> 调研全文：`docs/research/2026-09-28-monad-x402-landscape.md`；各子代理报告在会话工作流的 journal 里。
> 原则：追求最佳效果和体验，不设开发时长上限；另外标出「10/14 黑客松前必须能演示」的最小闭环（M0）。

## 0. 总体：三个项目各演一个角色

| 项目 | 角色 | 一句话 |
|---|---|---|
| **MoneySwitch** | 钱包（主角） | 给每个 AI 一把有额度、能撤销、能审计的钱：AI 时代的「人口钱包」 |
| **Monad 灵签** | 服务（卖家） | 最简单、最好玩、谁都能验证的 x402 服务：交易哈希就是签 |
| **灯城 Lantern City**（暂名） | 城（场所） | 人和 AI 在这里相遇、逛街、求签、买地、开店；每一盏灯都是一笔 Monad 上已结算的 x402 付款 |

三者合起来演示一条完整的链路：**人给 AI 一把钱（MoneySwitch）→ AI 在城里发现服务（灯城）→ 付款、拿结果（灵签）→ 链上可验证（Monad）**。

## 1. Monad 灵签（`repos/monad-lingqian`，v1 已在开发）

规格：`repos/monad-lingqian/SPEC.md`。

### 原理
- **签号 = uint256(交易哈希) mod 100 + 1**。
- 先结算、后出签。交易哈希在上链那一刻才产生，买家和我们都没法预知或挑选。
- 交易公开，任何人都能用 `/verify` 或自己算，结果一致。
- 结果丢了也能凭交易哈希免费找回。
- 一次付款一支签；三次付款就是三支签。

### 两个 x402 服务
- **抽签** `GET /qian`：0.01 USDC，返回签文，不做解读。解读默认交给买家自己的 AI，返回里附一句提示。
- **解签** `POST /jie`：Kimi 解读。输入签号或交易哈希（用交易哈希时会先核对是真抽出来的签），加上问题和生辰八字。**解读成功才扣钱**；生辰八字不存、不写日志。

### 版本
| 版本 | 内容 |
|---|---|
| v1（进行中） | API、免费 `/verify`、签库（观音灵签 100 签，至少两个独立出处交叉核对）、llms.txt、skill.md、openapi.json、测试网 e2e |
| v1.1 | 上主网（需要用户给 PAY_TO 并同意部署）；`/jie` 接 Kimi；`/.well-known/x402` 和 Bazaar 元数据；登记到 agent402 索引（发 POST 前先问用户） |
| v1.2 | 单独的精美页面：沿用老算命站的城隍红 #8A0000、金 #FFD700、纸色 #FFF8E7、书法字体、签卡双金边；分享链接 `/s/{txHash}`，页面由 `/verify` 复算，没法伪造；简体、繁体、英文三语 |
| 主舞台 | 灯城城隍庙的殿内（见第 2 节）|

## 2. 灯城 Lantern City（新项目，不改老站）

### 设计定调：夜色水墨
来自三套设计加评审的嫁接：
- **外圈地图**用「墨城」方向的正交舆图，用 PixiJS 渲染。不用等距视角（等距时高楼会挡住后排格子，框选出来是菱形），手机上最顺，也撑得住 1 万格。
- **城隍庙殿内**用「夜游」方向的 3D 场景（r3f），点进去才加载。惊艳集中在求签这一个时刻，3D 只做这一间殿。
- **信息层**用墨城方向的：紫印签号、候街 / 上街两级、钱袋浮层。
- **规则**用「庙会 402」方向的：上街准入、审批剧本、地契 tokenId = y*100+x。

**配色**
- 底色是夜 #0E091C，加墨线和灯笼金光。
- 朱砂 #8A0000 代表人文。
- Monad 紫 #6E54FF **只用在「链上可验证」的元素上**（印章、交易链接），让人一眼分清什么是链上事实。
- Monad 官方品牌色和字体见 monad.xyz/brand-and-media-kit。旧紫 #836EF9 不再使用。

### 世界布局（100×100）
- **内城**：中心约 24×24，保留不卖。
  - **城隍庙**在中心，进殿就是灵签：抽签、复算、解签。
  - **比武台**在庙前，代表本届黑客松：大屏轮播参赛项目（只放同意展示的团队），显示实时成交榜。
  - **赞助商幡旗**一排挂在比武台下。在主办方确认 logo 使用规则之前只放文字和品牌色。
  - **钱庄**是 MoneySwitch 展馆：腰牌（MoneyKey）、子腰牌（子 key）、流水簿（账单）。
  - **书局**：BookFinder 迁到 Monad 后开张。它目前在 Base Sepolia，接口 `/api/book` 已确认会返回 402。
- **夜市街**就是 x402 服务索引，一个服务一个摊。
  - 数据来源：卖家自己的 `/.well-known/x402`、Bazaar 用 `network=eip155:143` 过滤的结果、地主登记的 URL。agent402 按它的 ToS 只放外链，不转载。
  - **候街**：探测到合法的 402（网络 eip155:143，资产是 Monad USDC），摊位显示为暗色。
  - **上街**：链上查到至少一笔 USDC 付进它的 payTo，摊位点亮。
  - 灯的亮度按 7 天内**经过认证的**付款人数算，再加人工策展。只按独立地址数计挡不住开小号对刷，评审指出了这一点。
- **外城**：统一 0.1 USDC 一格，可以连片买；每个地址和每批都设上限（不然约 $800 就能被一个人买空）。四个城门留作以后扩展。

### 三个惊艳时刻
1. **开场**：宣纸上落下一滴墨，晕开成一条河。镜头沿河推进，灯笼按**真实的结算记录**从庙往外一圈圈亮起。之后每来一笔新结算，对应的摊位就升起一盏孔明灯。可以跳过。
2. **求签**（全站唯一的重动效）：
   - 摇签筒，手机上用陀螺仪。
   - 用 passkey 付款。
   - 交易哈希像老虎机一样滚动，定格后盖下一枚紫印，印文就是签号。
   - 点印章，展开 `uint256(0x…) mod 100 + 1 = 37` 的算式和区块浏览器链接。
   - 签卡展开，可以分享。
3. **我的地和走动的 AI**：
   - 买地后，墨线先勾出边，再晕染上色，最后落款。
   - AI 化身纸人，从城门走到它付过钱的摊位；铜钱划一道弧飞进摊位，灯笼一闪。脚印**只根据链上的 Transfer 画**，不信客户端自报。

### 交互
- **人买地**：框选时直接显示「N 格 · $X」。三种付法：
  1. **Mera passkey**：不用装插件。已核实 Mera 的 `toViemAccount` 支持 `signTypedData`，可以签 EIP-3009。
  2. **浏览器钱包**：`@x402/fetch` 加 `wagmiToClientSigner`，或官方的 `@x402/paywall`，上主网要把 `testnet` 改成 false。
  3. **「让我的 AI 买」**：生成一条 MoneySwitch 的 `paid_fetch` 指令，交给 AI 去付。
- **人求签**：见惊艳时刻 2。多支签合起来的解读，默认复制一段提示词给自己的 AI；也可以付费调 `/jie`。
- **AI 逛城**：提供 `llms.txt`、`skill.md`、`/.well-known/x402`、`/api/search`（返回价格、网络、接口地址和结算证据）、`/api/map`；AI 用 MoneyKey 付款。
- **装修**：
  - 模板加自定义图片（服务端重新编码并审核）。
  - 填入 x402 URL 后自动探测，生成「摊位证」。
  - iframe 只给白名单站点，并且不给 `allow-same-origin`；其余站点只放外链并加警示。
  - 装修权限：可以用 SIWE 或 passkey 证明自己是主人；通过 MoneySwitch 代买的，由服务端返回一次性 edit token（见下方「买地流程」）。

### 买地流程（吸取老站的漏洞）
老站的 `ON CONFLICT DO UPDATE` 会让任何人付钱就覆盖别人的格子，新流程：
1. 服务端报价：已占的格子、保留区直接拒绝，不发 402。
2. facilitator verify。
3. 预占：写入 authorization nonce 并设 TTL，用 `INSERT … ON CONFLICT DO NOTHING`；冲突返回 409，**不结算**。
4. settle，核对 receipt。
5. 主人 = 已验证的付款人，或请求里声明的 beneficiary（因为 MoneySwitch 用户在链上共用同一个付款地址）；同时返回 edit token。
6. 对账任务：用 `authorizationState(from, nonce)` 判断每一笔该补单还是释放。

**地权**：M0 靠「数据库 + 公开的结算交易」，任何人都能复核。M1 再发 ERC-721 地契（LandDeed，tokenId = y*100+x，链上防止重复铸造），为 Track 03 加深度。

### 技术
- **前端**：Next.js 15。
  - 地图：PixiJS v8 + pixi-viewport（惯性、双指缩放）。按 16×16 分块缓存成纹理；三级 LOD（远看色块、中间看建筑、拉近才有动画）；适配 DPR；画面静止时停帧。
  - 城隍庙殿内：r3f，加选择性 Bloom；手机降级成 2D 动画。
  - Tailwind 用 npm 包，不用 CDN。
- **后端**：Postgres（`UNIQUE(x,y)`、`UNIQUE(tx_hash)`），用 SSE 推送实时事件。
- **x402**：`@x402` 2.27 锁定版本，网络 eip155:143，facilitator 用 molandak。
- **索引**：M1 接 Envio，索引 Monad 上的 USDC Transfer，驱动灯光和脚印，同时报 Envio 赏金。Envio 是否支持 Monad 主网还没核实。

### 美术生产
- 先定一张风格母图，锁住视角和配色。
- 约 20 栋地标用 AI 生图（走 API，商用条款要核实），再人工修线、统一调色。
- 宣纸纹理和墨晕用 shader 程序生成，没有版权问题。
- AI 生成的图标注「AI 生成」；书法字体用 OFL 许可。
- 可以借老 Grid 的思路：只画视口内格子、大块只在左上角画一次、框选直接显示「N 格 · $X」、「给 AI 复制全部信息」文本块、skill.md 的章节结构。渲染层重写。

## 3. MoneySwitch：在两个演示里边用边改

### AI 人口钱包的原则（来自体验审计）
1. 每个 AI 一把 key，**链上也要认得出是谁付的**。现在所有 key 共用同一个服务端钱包签名（`apps/server/src/routes/agent.ts` 里的 `ctx.wallet.getSigner()`，已核实）。
2. 额度是一棵树，撤销时一路往下失效（v0.4 已实现）。
3. 能撤销，也能改：改额度、加域名。现在缺这个接口。
4. 每笔付款自带凭证：交易、浏览器链接、卖家、用途。
5. 给人看的账单按「买了什么」写，不只列 URL。
6. 分发给家人：发一条消息就能用，家人在别的机器上也连得上。
7. 「失败不收钱」两头对齐：卖家没结算，买家的额度立刻释放。
8. 人这一端用 passkey（Mera）当根：解锁钱包、审批、签发子 key。

### 改动清单
- **P0，演示阻断**
  - 把 `moneyswitch-server` 发到 npm。现在是 404，普通人第一步就走不通；发布需要用户的 OTP。
  - `sell` 加 `--network mainnet`，格子世界的摊位才能在主网收钱。
  - 客户端超时可配置、至少 60s，对象 body 默认加 JSON 的 Content-Type。否则 `/jie` 可能「付了钱没拿到结果」或返回 400。
  - fetch 和 history 返回 explorer_url、pay_to、description；修 TxLink 的 bug（员工视图的主网交易会链到测试网浏览器）。
- **P1，体验**
  - `PATCH` 修改 key 的额度和域名；allowed_hosts 支持通配，或从索引一键加入。
  - MCP 加 `discover`（Bazaar 143 + 灯城索引）和 `approval_status`。
  - 子 key 完成页加「发给家人」的文案、connect 命令和二维码；父 key 能看到每一笔。
  - 只读的 badge / viewer token，给灯城的「钱袋」浮层用：余额圆环、子 key 家谱、流水簿、被拒原因。
  - 付款请求支持 beneficiary 字段（格子和签归谁）。
  - 收费站和 sell 自动生成 llms.txt 和 Bazaar 元数据；额度用到 80% 或有待审批时发 webhook。
- **P2，探索**
  - **每把 key 一个链上身份**。可选方案：派生子地址、EIP-7702 或 session key。这是「AI 人口钱包」的核心研究题，要先写设计稿再动手。
  - **Mera passkey 当人的根**，对应赏金「One Passkey, Many Keys」。
  - **手机远程审批**，需要公网或中继。

### 演示剧本（钱庄里演）
1. 家长给孩子的 AI 发一块「子腰牌」，单笔上限 0.05。
2. AI 求签成功，头顶的钱袋条变短。
3. AI 想花 0.1 买地，超出单笔上限，被拒，门神盖一个红章。
4. 换成 Trial 预设（0.1 需要审批，因为 `policy.ts:104` 判断用的是 `>=`，已核实），AI 在摊前举着沙漏等批。
5. 人批准，地契到手。

目前审批只能在桌面控制台由管理员批，手机 passkey 审批是 P2。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| molandak 会不会给任意 payTo 结算，还没验证 | 灵签第一笔主网实付就能知道；不行备选 Solvador |
| 美术产能 | 风格母图加模板；3D 只做一间殿；其余用对 AI 生图最宽容的水墨 2D |
| 手机性能 | 性能预算、LOD、停帧；3D 降级成 2D |
| 抢格、重复付款、写库不一致 | 预占加 TTL 加对账；已占的格子不结算 |
| 刷亮度、囤地 | 按认证过的付款人加权，加人工策展；每个地址设上限 |
| 内容和 iframe 滥用 | 图片重新编码并审核；iframe 白名单，不给 allow-same-origin |
| 赞助商 logo 和他人项目的展示授权 | 先只放文字；问主办方；比武台展示需要对方同意 |
| 生辰八字的隐私 | 不存、不写日志；页面上事先告知会发给 Kimi |
| 老站 agent-verse.live 的覆盖漏洞 | 建议关掉购买，要用户同意（推送到 main 会直接上线）|

## 6. 待用户决定

1. 名字和风格：「灯城 · 夜色水墨」，还是「庙会 402（等距像素）」或「墨城（长卷）」。
2. 收款地址 PAY_TO（公开地址即可）；Kimi key 由用户自己写进本地 `.env`。
3. 美术要不要请一位画师手修约 20 栋地标，还是全部 AI 生成加程序化。
4. 新仓库（monad-lingqian、灯城）什么时候、要不要公开到 GitHub。
5. 要不要先做一个可点击的视觉样稿（开场加求签时刻），看了再定风格。
