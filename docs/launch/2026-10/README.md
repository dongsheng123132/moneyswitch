# MoneySwitch 第一轮试用与推广

本目录是待发布材料与执行建议；未发送帖子、邀请或消息。网站改动在独立分支上，尚未上线。奖励口径已按最新要求调整：会视试用与反馈情况酌情给予奖励，具体形式与标准另行说明，不承诺参与即得或固定金额。

## 先把定位讲成人能理解的场景

**正式定位：可云自托管的可编程多 Agent 支出钱包。**

对外第一句话：**多台设备、多个 AI，一个由你控制的支出钱包。**

补充解释：你把 MoneySwitch 部署在自己的服务器上，给电脑和云端的 Agent 分别发一把有额度的 MoneyKey。谁可以花、最多花多少、什么时候需要人批准，在同一处管理；已确认付款可以在账单中查到金额和链上交易号。

英文品类表述：**A self-hosted, programmable spending wallet for multiple AI agents.**

英文场景表述：**Many devices. Many agents. One spending wallet you control.**

“云”描述部署地点和远程访问方式，不表示 MoneySwitch 提供托管账户。“多 Agent”描述 HTTP 调用者共享服务，不表示已实现多种厂商的专有连接器。x402 放在“当前怎么付钱”这一层解释：目前支付支持的 USDC / x402 服务，不代付任意网站或 Codex、Claude 订阅。

## 为什么这次要改首页

旧首页以“Give your AI an API key for money”和 x402 机制切入，对单次付款讲得清楚，但没有先讲出多台设备上多个 Agent 的管理问题。首要按钮是 Star，试用和反馈入口不足。

这次页面结构调整为：

1. 场景与品类：多设备、多 Agent、一个由部署者控制的钱包。
2. 结构示意：设备上的 Agent → 各自的 MoneyKey → 钱包策略 → 付费 API。
3. 可执行入口：双语试用页、部署指南、反馈入口。
4. 当前能力：预算、域名控制、人工审批、撤销、付款记录。
5. 已有链上案例和具体技术路径，供想深入了解的人继续读。

## 第一轮怎么做

建议先找 **5–10 位**确实在多设备上使用 Agent 的开发者。这是工作量建议，不是已经招满的事实或对外名额承诺。第一轮先验证“有没有人真需要”和“能不能试完”，不要把浏览量当成功。

| 阶段 | 动作 | 要得到的证据 |
|---|---|---|
| 发布准备 | 浏览首页与双语试用页，确认新链接和反馈模板上线 | 入口可用，步骤和现版本一致 |
| 定向邀请 | 给熟悉的 Agent 开发者或自托管用户看招募短帖，由你发送 | 对方能描述一个具体付费任务 |
| 一起试用 | 按试用页跑完两个 Agent、一笔直接付款、一笔需审批付款、查账和撤销 | 记录卡点与实际结果，失败也记录 |
| 修首要卡点 | 按复现次数和阻断程度排序 | 下一位用户能独立通过前一位卡住的步骤 |
| 公开文章 | 先中文/英文产品思路文章，再招募帖；每个渠道保留相关语境 | 有具体问题的讨论和新的试用者 |
| HN | 由作者本人准备项目帖，提供可自行运行的入口并在线回答 | 技术讨论和可运行体验，而非纯招募 |

建议的内部复盘门槛：首批中至少 3 位独立完成接入，至少 2 位能说出下一次真实购买场景，再增加公开推广投入。这是本轮假设，样本很小，不能作为市场规模证据。

记录 5 件事：从哪里来、卡在哪一步、是否完成测试付款、是否体验审批/撤销、是否愿意用于一个具体下一次任务。可在 3–7 天后由你询问是否真正再用过；本次未创建自动提醒，也未发送消息。

## 对外边界

- 只讲现有能力。任务备注、按任务成本汇总仍是方向；子 Key 创建没有 UI。
- 达到或超过审批线（`>=`）会请求人工批准；超单笔/日/总额度仍会拒绝，批准不能越过硬限制。
- 私钥不随 Key/Skill 下发给 Agent。服务端仍是热钱包信任边界，能读钱包数据和解锁文件的人能用钱包；不要宣传“绝对防提示注入”。
- 一实例服务一个出资方；每个 Key 的额度不是独立托管余额。
- 测试币没有真实价值，不是可调用模型的美元 API 额度。自备主机可能有成本，水龙头和网络可能影响体验。
- 会视试用与反馈情况酌情给予奖励，形式与标准另行说明；不承诺参与即得或固定金额，不要求好评或转发，不编造名额、徽章、客户和成功率。
- 不说“唯一”“无人竞争”，不把 MetaMask 等产品的所有形态概括为只能弹窗。只解释自己的部署选择和需求。
