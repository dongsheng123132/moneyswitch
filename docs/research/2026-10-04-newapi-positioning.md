# MoneySwitch 能不能照 new-api 做？（2026-10-04 调研底稿）

> 起因：用户问 MoneySwitch 能否基本参考 new-api（QuantumNous/new-api、newapi.ai）来做，
> 定位是「企业负责人给员工的 agent 发 key」还是「第三方部署、陌生人注册存 USDC、发多把 key」。
> 方法：6 路调研 → 4 个视角独立分析 → 事实核查 + 魔鬼代言人，主会话复核了关键条文。
> 标注：✅ 亲自看到原文 / ⚠️ 二手 / 💭 推断。不是法律意见。

**结论**：new-api 从第一天起就是**中转站的收银后台**。增长靠的是先有的刚需（国内买不到 OpenAI）、
现成的运营者（one-api 存量），以及跟上游变化跟得极快（528 个 release）。
「企业 / 私有化」是 2026-05 才加上的合规措辞。

## 2. 钱这一侧的格局

- **闭环转卖**（运营者有货，用户的余额是不能提现的额度）：OpenRouter、BlockRun/ClawRouter（6.6k★，2026-02 创建，x402 + 刷卡充值发 key）。这些平台的条款都写明额度「不是钱、不能兑回」。⚠️
- **开环托管**（用户存钱，平台替他付给任意第三方）：只有持牌机构在做。Payman 自己承认这样做进入了 money transmitter 范畴；Catena 申请了 OCC 信托牌照；Crossmint 有 MiCA CASP 牌照。⚠️
- **企业内部给 agent 分额度**：Ramp、Mercury、Stripe Issuing、Ampersend、MetaMask Agent Wallet（Guard Mode 审批）。Ramp 的做法是：员工由管理员开通身份，agent 继承这个员工的额度和审批。✅（Ramp 页面原文）
- **开源、自托管、多用户的「x402 版 new-api」**：没有像样的项目。预算类的最高是 routeweiler 33★。✅
- **需求**：Monad 30 天外部只有 8 笔、3 个买家（agent402 原文 ✅）。整个 x402（以 Base 为主）30 天约 19 万个买方钱包、约 $1.1M，有刷量争议，买方留存约 6%。⚠️ **Monad 上冷清，不等于 x402 冷清。**
- x402 exact-EVM 规范已经把 **ERC-7710**（智能账户授权，可多次使用）列为第三种付款方式。✅（x402-foundation/x402 specs）但卖方支持率低。⚠️

## 3. 合规（不是法律意见）

- **银发〔2026〕42号**（2026-02-06 施行，八部门）**废止了 2021 年的 237 号文**。✅ pbc.gov.cn 原文
  - 第（一）条：境外单位和个人不得以任何形式向境内主体提供虚拟货币相关服务。
  - 第（七）条：互联网企业不得为相关业务提供经营场所、营销宣传、导流。
  - 第（十八）条：「为虚拟货币……相关业务提供服务的，依照有关规定予以处罚」；对明知境外违法、仍提供协助的境内主体追责。
  - 第（十九）条：相关民事行为无效，损失自担。
  - 全文**没有**明文写「托管 / 代付」；把公开托管定为「刑事级」是从兜底条款推出来的。💭
- **FinCEN 2019 指引**：hosted wallet 提供者就是 money transmitter；用自己的钱包给自己买东西的人不是；只做多签、没有完全独立控制权的服务商不是。✅
- **判断标准只有一条：谁能单方面动别人的钱。**
  - 「替每个客户部署一台、但运营者手里有自动解锁文件」仍然算托管。
  - 「商户转售」（运营者用自己的钱买、卖自己的额度）在境外可行，但在大陆没有合法的「人民币 → USDC」通道。
- 对照 new-api 中转站：它的监管落在网信层（以行政处罚为主），2026-09-15 网信办通报的「API中转站」案只给了警告。✅ 这和托管资金不是同一类风险。

## 4. MoneySwitch 代码现状（2026-10-04）

- 「一台服务器 = 一个出钱的人」写死在这些地方：钱包驱动只有一个 wallet.json；`money_keys` 表没有 owner 字段；admin_auth 不记录身份。
- 父 / 子 key 的后端完整，有测试：子树预算、祖先链检查、级联撤销。缺的是后台的 can_delegate 开关、员工入口，以及只有管理员能审批。
- **已知 bug**：账单接口只返回最近 200 笔，没有任何提示（`apps/server/src/routes/admin.ts:155-156`），和 SPEC §2「每一笔」不符。
- 付款前不检查钱包余额，所有 key 的额度加起来可以超过钱包里的钱。在「一个出钱人」形态下这没问题；如果多人共用钱包，就是 A 花掉 B 的钱。
- 如果照 new-api 做公开注册，需要：账户体系、多租户隔离、入账归属（USDC 转账没有备注字段）、提现、偿付对账。这些都是 L 级改动，而且都属于托管。

## 5. 未决

- 大陆企业用自有 USDC 支付境外 API，算不算 42 号文说的「虚拟货币相关业务」？外汇上怎么定性？
- 第（十八）条「为……提供服务」会不会覆盖发布开源自托管软件的个人？
- 虾盘云 / U-King 用户里有没有海外、持有 USDC 的人？已知 96.4% 的调用来自大陆 IP，海外模型几乎没人用。
- 有没有真实团队要「负责人 → 员工 → agent」两级？目前只在 token 侧看到需求。
